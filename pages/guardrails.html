Governance

Guardrails

The do's and don'ts, and the checks that enforce them. Most rules are automatic: breaking one fails the check, the commit or the release.

Do's and don'ts

Do
  • Use approved design tokens: --color-*, --space-*, --text-*, --radius-*, --shadow-*, --duration-*, --ease-*, --gradient-*.
  • Use established components before writing new CSS.
  • Follow semantic colour roles: brand fill for main actions, --color-accent-text for brand text, status tokens for status.
  • Keep to the type scale and the weights 400, 500 and 600.
  • Follow spacing and layout conventions (4px scale; work drawer 562px).
  • Follow theme specifications: test light, dark and high contrast.
  • Validate accessibility: contrast, labels, focus, touch targets.
  • Document new patterns through an RFC.
Don't
  • Hard-code colours, sizes, shadows or timings.
  • Introduce inconsistent spacing.
  • Create duplicate components (a second confirm dialog, toast or filter drawer).
  • Override global tokens without approval.
  • Introduce unapproved fonts.
  • Introduce arbitrary animation timings.
  • Bypass accessibility requirements or remove focus outlines.
  • Modify published components or releases directly.

How the guardrails are enforced

Token build

Rejects raw values in semantic tokens, broken references, a drifted brand colour and any colour pair below WCAG AA in any of the four modes. tools/build.mjs

Guardrail check

Scans CSS, HTML, JS and TSX in any prototype or product for the automatic rules below, with file and line. tools/check.mjs

Self-test

A deliberately bad prototype must trip every automatic rule; a clean one must pass. Stops the checks from quietly breaking. tools/test.mjs

Commit and release gates

The pre-commit hook runs the build, check and release verification. tools/release.mjs refuses to publish if anything fails, and published files are checksummed.

Rule register

From governance/rules.json. check: automatic in any repo. build and release: automatic in this repo. review: a reviewer confirms it.

AI assistants

The same rules and checks apply whoever writes the code. AI assistants read AGENTS.md, which tells them never to invent tokens, duplicate components or edit published packages, and to flag missing pieces as proposals. Anything they still get wrong fails the same check. No rule depends on a particular AI tool.

Running the check

# a prototype folder or file
node tools/check.mjs ../antz-command-centre

# a product, report mode while a module is migrating (never fails)
node tools/check.mjs ../web-dashboard/src --report

# machine-readable, for CI or the health dashboard
node tools/check.mjs ../web-dashboard/src --json
